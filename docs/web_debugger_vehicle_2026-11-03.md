# Web 调试器实车性能验证（2026-11-03）

## 实测结论

- 功能验证、无硬件回归和真实页面联调通过；已完成旧版6轮、首次异步版10轮、最终缓冲复用版10轮测量。
- 最终版视频加遥测两轮为 **49.83 / 60.93 FPS**，对应关闭 Web 为 **64.70 / 60.47 FPS**；第一轮未达到95%吞吐与视觉P99门槛，第二轮达到。**总体性能目标尚未全部达成**。
- 规划周期P99各轮约10.3 ms；慢视频和慢遥测连接均实际发生背压丢弃。无观看者与纯遥测模式的图像复制次数为0。
- 固定尺寸最终版每个视频运行只分配1张原图、其余复用；这证明消除了反复分配，不能据此宣称实车FPS或复制耗时已稳定改善。

## 结果范围

使用实车海康相机（原图1440×1080）与 `/dev/ttyUSB0` 反馈运行 `auto_aim_debug_mpc`，保留正常控制及开火逻辑。当前可测场景没有跟踪目标，因此结果覆盖相机、检测、通信及调试数据路径，不代表有目标时 MPC 求解、跟踪和实际射击的负载。

每轮初始化完成后预热 5 秒，测量 30 秒，每种模式重复两轮。相同 sentry 配置、YOLO 模型、相机参数与原 Plotter 设置；关闭本地窗口；视频上限 30 FPS、宽 640、JPEG 质量 60。缺少的七项 MPC 参数经用户确认采用 standard4 同组值。

客户端使用本机回环连接，被动读取视频/遥测；慢客户端完成握手后停止读取。CPU 不包含观看者进程，100% 表示一个核心。未测远程 Wi-Fi 或浏览器在另一台设备上的网络状况。主机运行桌面应用，关闭 Web 的重复测量也有明显波动，不能将跨轮全部 FPS 差异归因于代码改动。

旧版基线是修改前工作树的快照，仅加入相同的限时统计；该快照包含当时尚未提交的 Web 改动。首次异步版尚未复用原图缓冲；最终版增加最多三张原图的所有权复用。旧版源码快照保存在测量机的 `build/web_baseline_source`，不包含在仓库中。

## 同进程复制对照

为避免把整机波动误判成分配收益，另在同一进程用8张1440×1080源图轮换，对四种路径按打乱的50样本块取样。每路径预热100次，再分三轮各测3000次，共9000次；源图与可复用缓冲提前分配，不改CPU亲和性或OpenCV线程设置，不涉及相机、YOLO或网络。

| 路径 | 均值 ms | P50 ms | P95 ms | P99 ms | 最大 ms |
|---|---:|---:|---:|---:|---:|
| 旧版：缩放至640宽 | 0.2302 | 0.2113 | 0.3573 | 0.4343 | 0.7163 |
| 新建完整原图复制 | 0.2453 | 0.2284 | 0.3797 | 0.5232 | 0.9982 |
| 复用一张原图（实车稳定态） | 0.2459 | 0.2306 | 0.3745 | 0.4610 | 0.9976 |
| 轮换三张原图（并行时上界） | 0.2896 | 0.2656 | 0.4491 | 0.5741 | 1.0800 |

复用一张缓冲的均值与新建复制基本相同，P99在本次对照中较低；轮换三张缓冲均值较高。因此保留按需回收、稳定态通常只用一张的实现，不预先强制轮换三张。该对照仅隔离复制/分配成本，不能代替实车负载验证。完整原图仍需复制约4.45 MiB，原图复制不会必然比直接降采样更快。

## 验证与复现

- Release 目标构建：`cmake --build build --target auto_aim_debug_mpc web_debugger_stress_test -j2`。
- `ctest --test-dir build -R "^web_debugger_stress_test$" --output-on-failure`：包括256项 SPSC、并发 FIFO、图像/标注所有权、复用和分辨率切换、无视频遥测、过期/满载、双通道、慢客户端、无效调参与重连。
- `tests/web_debugger_frontend_test.cjs`：离线 Chrome 回归通过，覆盖3000点上限、20Hz绘图路径、500ms过期、序号/null断线、暂停视频、遥测重连、视频解码、EKF和调参。
- 构建修复仅对缺少的两个可选测试增加存在条件，并移除本自瞄目标未使用的 auto_buff 链接；其他能量机关目标未作为本次构建验收范围。

最终矩阵命令：
```bash
python3 tools/web_debugger_benchmark.py --binary build/auto_aim_debug_mpc \
  --config configs/sentry.yaml --output-dir build/web_benchmark_vehicle \
  --label pooled --modes off,no_client,telemetry,both,slow --repeats 2 --warmup 5 --seconds 30
```

该命令运行正常闭环控制。环境信息：[环境与原始测量数据](web_debugger_vehicle_2026-11-03_data.json)。每个 JSON 保存全部时间指标的 count/mean/P50/P95/P99/最大值、完整性标记、进程资源与客户端实际接收数。
