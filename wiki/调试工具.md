# 调试工具

`debug/` 包含 Web 可视化调试器、DebugBus 和动态滤波器参数管理器。`auto_aim_debug_mpc` 已接入视频、EKF 参数面板及规划遥测曲线。Web 服务与算法运行在同一进程，缩放、JPEG 编码、Web 消息的 JSON 序列化及 Web 网络发送由后台线程处理；视觉线程仍承担采样后的原图复制和结构化调试数据构造成本。

## 启用 Web 调试器

在 YAML 中设置实际生效的配置项 `debug_bus.sinks.web`：

```yaml
debug_bus:
  sinks:
    web:
      enabled: true
      port: 8080
      bind: "0.0.0.0"
      max_fps: 30        # 视频帧率上限，范围 1–120
      jpeg_quality: 60   # JPEG 质量，范围 10–95
      max_width: 640     # 视频最大宽度，范围 160–4096
```

除 `enabled` 外，上述字段均可省略，默认值如示例；超出范围的推流参数会被限制在对应范围内。`debug_display.window` 控制本地窗口，不能用它替代 Web sink 的启用项。

```bash
./build/auto_aim_debug_mpc configs/sentry.yaml --headless=true --web=on
```

访问 `http://<机器人IP>:8080`。`0.0.0.0` 是服务监听地址，浏览器使用机器人实际 IP。`--headless=true` 关闭本地窗口；`--web=auto` 默认遵循 YAML，`--web=on/off` 只覆盖本次进程的 Web 开关，不写回配置。

网页保留检测框、重投影、EKF 和调参面板，增加独立遥测曲线：

- 默认显示 yaw、pitch 各自的实测、目标和规划三条曲线；角度、速度、加速度、位置及状态字段均可勾选，使用原始字段名和单位。
- 页面使用本地 Canvas，无 CDN 或外网依赖；最多保留 3000 个遥测样本，绘图上限 20 Hz，隐藏页面时暂停曲线绘制。可选 5/10/30 秒显示窗口，实际历史长度受样本容量限制。
- 缺失序号和 `null` 处断线；超过 500 ms 没有新样本显示“遥测：已过期”。遥测重连成功时清空旧历史。
- “视频推流”开关关闭视频 WebSocket；遥测连接保持工作。EKF、推流设置及调参使用视频连接，暂停期间不会收到这些更新，也不能提交调参；重新开启视频后恢复。
- 视频画质、帧率设置对所有视频客户端生效，重启后恢复 YAML。图像超过 `max_width` 时在后台等比缩小，标注按实际输出宽高分别缩放。

### 数据路径与性能指标

视觉侧先检查视频客户端和采样间隔，获准后再构造 Web 专用重投影及检测元数据。提交时复制原始图像，通过 `try_lock` 写入容量为 1 的最新帧槽；竞争时丢弃调试帧，新帧可覆盖尚未处理的旧帧。调用返回后，相机或调用方可复用原图。固定尺寸下复用至多三张原图缓冲，后台完成最后一次像素读取后归还；首次采样及尺寸变化时仍可能分配。后台负责缩放、编码和发送，慢客户端发送缓冲未清空时跳过新数据。

遥测由规划线程提交固定大小快照，使用容量 256 的单生产者/单消费者队列；队列满时丢弃新样本。后台约每 50 ms 批量发送，排空时丢弃超过 250 ms 的积压样本。没有遥测客户端时，提交直接返回。遥测与视频共用后台线程，编码负载仍可能造成遥测发送抖动，这不是硬实时隔离。原 Plotter 路径继续运行，其原有 JSON 构造和 UDP 发送成本仍在规划线程中。

网页指标：

| 指标 | 含义 |
|------|------|
| FPS | 本页面实际绘制的视频帧率 |
| Proc / `proc_ms` | `camera.read` 返回后至准备好该帧调试数据的处理耗时，不含提交复制、编码和网络传输 |
| Frame age / `age_ms` | 采集时间至服务端生成帧元数据的耗时，不含后续网络和绘制；采集时间无效时不显示 |
| 视频 Dropped | 当前视频连接因发送缓冲未清空而跳过的帧数，重连清零；不含限频、单槽覆盖或锁竞争 |
| 遥测丢弃：队列 / 过期 / 本连接 | 全局入队满载丢弃、全局后台过期丢弃、该遥测连接因背压跳过的样本累计数；只有“本连接”在重连时清零 |
| EKF STALE | 最近收到的随帧 EKF 状态距更新超过 300 ms；没有新视频帧时不会独立推送 EKF 状态 |

`DebugBus::stats()` 返回 `DebugStats`。`frames_accepted/overwritten/busy` 分别统计入槽、旧帧覆盖和锁竞争丢弃；`frames_sent` 按客户端统计已交给发送路径的帧数，不代表浏览器完成绘制。`video_client_dropped`、`telemetry_client_dropped` 汇总所有相应连接的背压丢弃，后者按样本计数。`telemetry_accepted/full_dropped/expired_dropped/batches` 统计遥测队列及非空批次。图像复制与 JPEG 编码另有 `*_count`、`*_total_ns`、`*_max_ns`；限频和无客户端时跳过的帧没有单独计数。`raw_frame_allocations/reuses` 分别统计原图缓冲新分配与固定尺寸复用次数。计数从服务实例创建开始累计，`shutdown()` 后仍能读取最终计数。

### WebSocket 协议

同一端口提供两个独立端点，视频与遥测序号各自递增：

| 端点 | 服务端消息 | 用途 |
|------|------------|------|
| `/ws` | 二进制视频帧；文本 `param_sets`、`ekf_state`、`stream`、`error` | 视频、EKF 与调参控制 |
| `/ws/telemetry` | 文本 `telemetry_hello`、`telemetry` | 规划遥测；不发送视频或参数消息 |

视频二进制布局保持兼容：`uint32 小端元数据字节长度 | UTF-8 JSON 元数据 | JPEG`。元数据包含 `seq`、`w`、`h`、`jpeg_bytes`、`detections`、`reprojections`、`proc_ms`、`dropped`，采集时间有效时另有 `age_ms`。`pts` 已变换到 JPEG 尺寸。客户端在 `/ws` 发送 `{"cmd":"set_stream","max_fps":30,"jpeg_quality":60,"max_width":640}` 修改设置，可只提供需要修改的整数字段；`update_param` 修改滤波器参数，非法输入返回 `error`。

遥测握手消息为 `{"type":"telemetry_hello","capacity":256,"batch_ms":50}`。批次格式为：

```json
{
  "type": "telemetry",
  "samples": [{"seq": 42, "t": 0.42, "monotonic_ms": 1234567.89, "gimbal_yaw": 0.1, "control": false, "target_valid": false, "outpost_valid": false}],
  "dropped": {"full": 0, "expired": 0, "client": 0}
}
```

示例只展示部分样本字段；实际每个样本包含下表全部字段。`t` 是规划线程启动后的秒数；`monotonic_ms` 是入队时的单调时钟毫秒值，不能当作墙上时间或相机采集时间。`seq` 在有遥测观看者时随提交尝试递增，队列满载也会留下序号缺口。视频与遥测不保证逐帧对应。

| 字段 | 单位 / 类型 | 有效条件 |
|------|-------------|----------|
| `gimbal_yaw`, `gimbal_pitch` | rad | 有限数；yaw 保留现有 Plotter 的 `-gs.yaw` 符号 |
| `gimbal_yaw_vel`, `gimbal_pitch_vel` | rad/s | 有限数，保留现有符号 |
| `target_yaw`, `target_pitch` | rad | `target_valid && control`；它们来自规划解算，失败时不显示默认零值 |
| `plan_yaw`, `plan_pitch` | rad | `control` |
| `plan_yaw_vel`, `plan_pitch_vel` | rad/s | `control` |
| `plan_yaw_acc`, `plan_pitch_acc` | rad/s² | `control` |
| `target_z`, `target_vz`, `w` | m、m/s、rad/s | `target_valid` |
| `target_z0`, `target_z1`, `target_z2` | m | `target_valid && outpost_valid` |
| `target_z0_var`, `target_z1_var`, `target_z2_var` | m² | `target_valid && outpost_valid` |
| `target_last_id`, `target_update_count`, `target_jumped`, `reprojection_aim_id` | ID、次数、0/1、ID | `target_valid && outpost_valid` |
| `fire`, `fired` | 0/1 | 始终输出；分别是规划开火状态、弹丸计数递增检测 |
| `control`, `target_valid`, `outpost_valid` | JSON 布尔值 | 始终输出；网页按 0/1 绘图 |

不满足条件或不是有限数的数值字段输出 `null`。`outpost_valid` 表示当前快照包含前哨站专用状态；不应据此把其他目标的前哨站高度或 ID 当作零值。

## DebugBus — 调试事件总线

推荐先取得一次性 `FrameTicket`，再准备 Web 专用数据；`post(ticket, data)` 消费凭证，不会再次限频。旧接口 `post(data)` 保留，内部执行同一套预检查和提交，但无法跳过调用方事先完成的数据构造。示例：

```cpp
#include "debug/debug_bus.hpp"
#include "debug/param_tuner.hpp"
#include <utility>

// 初始化一次，在视觉、规划生产线程启动前完成。
debug::ParamTuner::instance().load_from_yaml(config_path);
auto & bus = debug::DebugBus::instance();
bus.load_config(YAML::LoadFile(config_path));

// 单个视觉生产线程；原始图像不要预先绘入仅供 Web 的标注。
auto ticket = bus.try_begin_frame();
if (ticket) {
  std::vector<debug::ReprojectionData> reprojections;
  // 仅在这里构造 Web 所需的重投影；检测结果 armors 来自主算法。
  const double proc_ms = std::chrono::duration<double, std::milli>(
    std::chrono::steady_clock::now() - proc_start).count();
  bus.post(std::move(ticket),
           {frame, &armors, std::move(reprojections), proc_ms, capture_time});
}

// 独立的单个规划生产线程，直接从已有局部变量填充快照。
debug::TelemetrySample telemetry;
telemetry.t = elapsed_seconds;
telemetry.gimbal_yaw = -gs.yaw;
telemetry.gimbal_pitch = gs.pitch;
telemetry.target_valid = target.has_value();
telemetry.control = plan.control;
telemetry.plan_yaw = plan.yaw;
telemetry.plan_pitch = plan.pitch;
// 完整字段赋值参考 src/auto_aim_debug_mpc.cpp。
bus.post_telemetry(telemetry);

// 所有视觉、规划生产线程退出并 join 后，停止并等待 Web 线程。
bus.shutdown();
```

`FrameTicket` 只能移动、不能复制，至多消费一次；申请时已占用该次采样机会，即使之后未提交或提交丢弃也不会返还。仅支持一个视觉生产者及一个独立遥测生产者。生产线程运行期间不得调用 `load_config()`、`add_sink()` 或 `shutdown()`，也不能持凭证跨越这些生命周期操作。

`FrameDebugData` 的图像和装甲板指针只保证在 `post()` 期间有效。Web sink 在返回前复制所需像素和元数据，调用方无需提前 `clone()`；自定义 sink 也必须遵守此所有权约定。原图复制、元数据分配和操作系统调度仍有成本，应通过下述测量验证对主流程的实际影响。

## ParamTuner — 动态参数调节

在 YAML 中通过实际键名 `filter_param_sets` 定义参数集，例如：

```yaml
filter_param_sets:
  - name: "slow"
    v1: 10.0
    v2: 0.5
    R_yaw: 0.004
    R_pitch: 0.004
    R_distance: 0.09
    angular_velocity_threshold: 2.0
  - name: "normal"
    v1: 100.0
    v2: 400.0
    R_yaw: 0.004
    R_pitch: 0.004
    R_distance: 0.09
    angular_velocity_threshold: 8.0
  - name: "fast"
    v1: 500.0
    v2: 1000.0
    R_yaw: 0.002
    R_pitch: 0.002
    R_distance: 0.05
    angular_velocity_threshold: 999.0
```

按阈值递增配置：系统根据目标角速度绝对值选取第一个阈值大于角速度的参数集，超过所有阈值时使用最后一组。省略 `filter_param_sets` 时使用内置默认值。网页可以编辑各组参数；提交的数值必须是有限正数，阈值必须保持严格递增。网页修改只影响运行时，不会写回 YAML。选择编辑标签不会改变系统自动选择的运行参数集。

## 回归测试与限时性能测量

无硬件 C++ 回归使用真实 loopback WebSocket，覆盖预采样、一次性凭证、原图所有权、后台缩放及标注、队列满载/过期、遥测独立更新、慢客户端、非法调参和正常退出：

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=ON
cmake --build build --target auto_aim_debug_mpc web_debugger_stress_test -j2
ctest --test-dir build -R '^web_debugger_stress_test$' --output-on-failure
```

浏览器回归不连接车辆，模拟两个 WebSocket 端点，检查视频解码、EKF/调参、曲线选择、3000 样本边界、无效值及序号缺口断线、隐藏页面、过期状态、暂停视频及重连。需要现有 Node.js、Playwright ≥ 1.48 和 Chrome/Chromium；脚本不会安装依赖：

```bash
PLAYWRIGHT_MODULE_PATH=/path/to/playwright-core CHROME_BIN=/path/to/chrome \
  node tests/web_debugger_frontend_test.cjs debug/static/index.html /tmp/spr_web_debug.png
```

已能通过普通 Node 模块解析找到 `playwright-core` 时可省略 `PLAYWRIGHT_MODULE_PATH`；使用 Playwright 自带 Chromium 时可省略 `CHROME_BIN`。HTML 路径和截图路径均可省略，默认测试仓库内页面，不生成截图。

### 原图复制对照

`cmake --build build --target web_debugger_copy_benchmark -j2` 后运行 `./build/web_debugger_copy_benchmark`。该程序无需相机和串口，在同一进程、1440×1080 原图、8 张源图轮换的条件下，对照旧版缩放、新分配原图复制、复用一张和轮换三张缓冲；预热后打乱采样块顺序，输出三轮的均值与分位数。它隔离复制/分配成本，不等同于实车 YOLO、相机和编码共同运行时的端到端性能。

### 单轮实车测量

以下命令运行正常闭环视觉、云台控制及开火逻辑，不是仅收图模式。`--headless` 只关闭本地窗口，浏览器观看者也不会改写参数：

```bash
./build/auto_aim_debug_mpc configs/sentry.yaml \
  --headless=true --web=on \
  --benchmark-warmup=5 --benchmark-seconds=30 \
  --benchmark-output=/tmp/spr_web_benchmark.json
```

| 选项 | 默认值 | 含义 |
|------|--------|------|
| `--headless` | `false` | 强制关闭本地窗口；否则遵循 YAML 及显示环境检测 |
| `--web` | `auto` | `auto/on/off`：遵循 YAML、开启、关闭 Web sink |
| `--benchmark-seconds` | `0` | 大于零时启用限时测量；零为普通运行 |
| `--benchmark-warmup` | `5` | 模型、相机及规划器初始化完成后的预热秒数 |
| `--benchmark-output` | 空 | 测量 JSON 文件路径；父目录须已存在；省略时仅输出日志 |

到期后在视觉循环边界退出，停止规划线程并 join，发送现有退出控制消息，再关闭 Web 线程并汇总。设备读取若卡住，循环本身不能立即响应时间限制；批量运行器会把超时作为失败处理。提前中断的结果有 `measurement_complete=false`，不能当作完整 30 秒测量。

每个指标使用固定容量 65536 的采样存储，测量器在采样期间不写逐帧日志；结束后输出 `count/retained/overflow`、均值及 P50/P95/P99/最大值，时间单位为 ms。`overflow` 非零时分位数仅覆盖已保留样本，应缩短测量或降低采样量后复测。

| JSON 指标 | 测量边界 |
|-----------|----------|
| `algorithm_ms` | 相机读取返回至跟踪和目标队列更新完成，位于 Web 预采样之前 |
| `frame_loop_ms` / `frame_period_ms` | 整轮视觉耗时（含相机等待）/相邻视觉循环开始间隔 |
| `frame_age_ms` | 相机采集时间至主线程完成调试提交，与网页编码后 `age_ms` 的结束点不同 |
| `debug_prepare_ms` / `frame_submit_ms` | Web 预检查、图元构造及提交合计/实际提交调用；未提交时后者是空分支计时 |
| `frame_copy_ms` / `encode_ms` | 提交中的完整原图复制/JPEG 编码；`encode_ms` 不含后台缩放 |
| `plan_work_ms` / `plan_period_ms` | 规划、控制发送、遥测提交和原 Plotter 输出合计，不含循环末尾 10 ms 睡眠/相邻规划开始间隔 |
| `telemetry_submit_ms` | 固定快照进入 `post_telemetry()` 的调用耗时，不含快照赋值和原 Plotter JSON 构造 |

`vision_fps` 使用测量窗口内完成的视觉帧数除以有效测量时长；`measurement_start_monotonic/end_monotonic` 给出测量窗口。`debug_run_counters` 是服务运行期累计值，包含预热阶段，与仅在测量窗口采样的分布统计范围不同。

### 批量实车对比

在同一场景、模型、相机曝光、MPC、Plotter 和主机负载下，依次比较关闭 Web、开启无观看者、仅遥测、视频加遥测、再加慢客户端；每种默认重复两轮：

```bash
python3 tools/web_debugger_benchmark.py \
  --binary build/auto_aim_debug_mpc --config configs/sentry.yaml \
  --output-dir build/web_debugger_benchmark/current --label current \
  --modes off,no_client,telemetry,both,slow --repeats 2 --warmup 5 --seconds 30
```

运行器只创建被动观看连接，不发送调参或推流设置命令。`slow` 同时保留正常视频/遥测观看者和各一个握手后不再读取的慢连接；`video` 模式也可单独指定。默认端口为 8080，使用其他 YAML 端口时须同步传入 `--port`。脚本为每轮保存 JSON 和进程日志，校验完整测量、相机帧数以及正常观看者实际收到的数据。

CPU 和 RSS 来自测量窗口内每 200 ms 的进程采样，不包含观看者进程；CPU 百分比以一个核心为 100%，多线程时可超过 100%。`backpressure_observed` 标记该轮是否实际发生视频/遥测背压丢弃；未发生时不能声称已经完成对应的慢客户端压力验证。观看者的目标有效及控制样本计数有助于区分有目标闭环场景与无目标场景。

当前 `sentry.yaml` 使用海康相机、`/dev/ttyUSB0` 和已有 Plotter 目标地址。已确认的 MPC 配置为 yaw 最大加速度 50 rad/s²、pitch 最大加速度 100 rad/s²，二者 `Q=[9e6, 0]`、`R=[1]`；对比前后应记录并保持所测配置一致。视频基准为 30 FPS、640 宽、质量 60，实测比较期间关闭本地窗口。

验收目标是视频加遥测的视觉吞吐至少为关闭 Web 的 95%，视觉及规划耗时 P99 的增幅不超过“关闭 Web 基线的 5% + 0.5 ms”，并检查慢连接是否进一步影响生产线程。完整原图复制的成本单独查看 `frame_copy_ms`。实车对比已完成，门槛未在所有轮次通过；完整表格、限制和原始 JSON 见 [实车测量报告](../docs/web_debugger_vehicle_2026-11-03.md)。

## PlotJuggler 使用

PlotJuggler 是官方推荐的实时曲线绘制工具，用于可视化 EKF 状态、预测轨迹、云台响应等数据。本项目通过 `tools::Plotter` 工具类以 UDP 协议向 PlotJuggler 发送 JSON 格式数据。

### 安装 PlotJuggler

```bash
sudo apt install plotjuggler
# 或从源码编译：https://github.com/facontidavide/PlotJuggler
```

### 启用方式

`Plotter` 默认向 `127.0.0.1:9870` 发送 UDP 数据，用法如下：

```cpp
#include "tools/plotter.hpp"

tools::Plotter plotter;   // 默认 127.0.0.1:9870
// tools::Plotter plotter("192.168.1.100", 9870);  // 远程地址

// 构造 JSON 数据并发送
nlohmann::json data;
data["timestamp"] = current_time;
data["yaw"]       = target_yaw;
data["pitch"]     = target_pitch;
data["distance"]  = target_distance;
data["vx"]        = target_vx;
data["vy"]        = target_vy;

plotter.plot(data);
```

已在以下兵种 main 函数中默认启用 Plotter：
- `standard.cpp` / `standard_mpc.cpp`
- `mt_standard.cpp` / `mt_auto_aim_debug.cpp`
- `sentry.cpp` / `sentry_multithread.cpp`
- `uav.cpp` / `uav_debug.cpp`

### PlotJuggler 使用步骤

1. **启动 PlotJuggler**：
   ```bash
   plotjuggler
   ```

2. **配置数据源** (Streaming)：
   - 点击菜单栏 **Streaming → Start UDP Server**
   - 端口填写 `9870`（与代码中一致）

3. **拖拽曲线**：
   - 左侧数据树中将显示收到的 JSON 字段（如 `yaw`、`pitch`、`distance`）
   - 将字段拖入右侧绘图区即可显示实时曲线
   - 按住 `Ctrl` 可多选同时绘制

4. **保存/加载布局**：
   - 配置好曲线布局后，保存为 `.xml` 文件（如项目中的 `mpc_layout.xml`、`buff_layout.xml`）
   - 下次启动时通过 **File → Load Layout** 快速恢复

5. **常见用途**：
   - 观测 EKF 收敛过程（位置/速度/角度估计值）
   - 评估弹道解算效果（pitch 角度随时间变化）
   - 对比预测轨迹与实际目标运动
   - 监控打符时的能量机关旋转速度预测

## 常见问题 (FAQ)

| 问题 | 原因 | 解决 |
|------|------|------|
| 编译时报 `OpenVINO_DIR` 未设置 | OpenVINO 未安装或路径不正确 | `export OpenVINO_DIR=/opt/intel/openvino_2024.6.0/runtime/cmake` |
| `sudo: dpkg: 未找到命令` | Docker 内缺少 dpkg | 使用 Docker 编译而非直接运行 shell 命令 |
| 相机打开失败 | 权限不足 / USB 端口被占用 | `sudo usermod -a -G dialout $USER`，重新登录；检查 `ls /dev/video*` |
| `can0: 未找到设备` | CAN 适配器未连接或驱动未加载 | 检查 USB2CAN 是否插入；`sudo modprobe can`；查看 `dmesg` |
| 自瞄不准 | 标定参数不准确 / 弹道补偿未调好 | 重新标定相机 → 手眼标定 → 调整 `yaw_offset` / `pitch_offset` |
| 帧率低 | 推理耗时过长 / 曝光时间太长 | 启用 GPU 推理；缩小 ROI；调低分辨率；使用多线程架构 |
| 程序启动后闪退 | 配置文件路径错误或模型文件缺失 | 确认 `assets/` 下有对应的 `.xml/.onnx` 文件；检查配置文件路径 |
| 串口 `gimbal` 设备不存在 | udev 规则未生效 | 重新执行 `sudo udevadm control --reload-rules && sudo udevadm trigger`；确认 VID/PID/序列号正确 |
